# Reading-session records

## Function

A reading-session record preserves how source understanding developed before selective synthesis. Keep it chronological and minimally edited. It is provenance for later reading cards, not a card itself, a card-production log, or an argument map.

Choose the record language from the writer's explicit request, the active record, or the local dialogue when no record exists. Render all headings, field labels, and status labels naturally in that language. Preserve each writer question in the language in which it was asked and preserve quotations in the source wording actually inspected.

## When to preserve one

In a declared local reading project, a dialogue becomes eligible for preservation when it contains multiple substantive source questions. Do not write it immediately for that reason alone. Promote it to a session record only at a writer-confirmed checkpoint when:

- the writer asks to save, pause, close, synthesize, or change phase;
- the writer confirms a checkpoint proposed by Codex; or
- the writer directly requests one or more reading cards that will draw on the dialogue.

Codex may propose a checkpoint when a coherent line has reached temporary stability, the writer appears to be changing topics, several distinct reusable units have emerged, or the discussion is becoming long enough that a recoverable boundary would help. Ask once and continue the dialogue if the writer declines or does not accept. A proposal alone is not authorization to write a file.

Treat the ongoing chat as transient working state, even when the product retains its history. Do not create a project artifact for a one-off question unless the writer asks. During an active session, append live only when requested; otherwise wait for a writer-confirmed checkpoint.

Once promoted, keep the session as persistent provenance rather than temporary cache. Preserve it before creating any card that draws on it.

## Record shape

Keep the reader close to the chronological dialogue. Use the shortest useful source note; there are no mandatory header fields. A single source line is often sufficient. Omit “Session information” when it would merely wrap that line or repeat what the title and citations already establish. Add coverage, date, or a source limitation only when it matters for this record. Preserve an existing artifact’s language and the author-reviewed form. Apply the source-note relevance and author-review rules in SKILL.md.

```markdown
# Reading session: Topic

Source: Author, title; link or locator when useful.

## Reading dialogue

### Q1: Substantive reading question

**Writer:** Original question

**Codex:** Answer given at the time

## Follow-up

- Related card: Link, if one was created
- Open source check: Specific unresolved check, if one remains
```

This example is a flexible starting point, not a form to complete. Add per-answer locators or provenance notes only when they clarify something not already stated. Supplementary sources can be cited at the relevant answer rather than collected again in the header. Retain a concrete limitation such as an illegible quoted line when it affects the claim; omit routine extraction and language-history details.

Preserve the writer's questions verbatim. Preserve Codex's answers verbatim when practical; if a response must be shortened, mark it `[edited for length]` or a clear localized equivalent, and do not strengthen its claims. A descriptive Q heading may summarize the exchange, but it must not replace the writer's wording or turn a model formulation into the writer's question. Retain substantive follow-ups in their actual order under the relevant Q or as the next Q.

The reading dialogue contains only exchanges that develop understanding of a source, an interpretation, or a source-grounded extension. A request to locate a source belongs in session information or a brief source-establishment note before the dialogue. Checkpoint consent, card proposals, choices about card title or structure, implementation plans, and artifact review logistics are not reading questions and must not be numbered as Q&A. In the follow-up section, give only links to related artifacts, specific unresolved checks, or a brief boundary note needed to explain the session's continuation; do not reproduce the negotiation or duplicate the dialogue as a mini-card. Use the integrity rule below for substantive corrections; do not append routine revision histories.

## Integrity rules

- Keep source reconstruction, model interpretation, writer response, and open questions distinguishable.
- When an uncorrected earlier answer would mislead later reading, append a concise dated correction or link to the corrected card; do not repeat the full diagnosis in both artifacts. Never silently repair an earlier answer. Honor the writer’s deliberate edits or deletions of correction notes.
- Retain the order of substantive questions, including detours and changes of understanding that matter.
- Add locators only when verified; do not manufacture retrospective precision.
- Let later reading cards link and selectively condense the session. Never delete the session because cleaner cards now exist.

## Optional question-path synthesis

Use only when the writer explicitly asks how a reading question developed across exchanges or sessions. Work from dialogue and records placed in scope. Select the initial question, consequential textual clarifications, changes in the question, and what remains open. These are useful elements, not required headings or a fixed early/middle/late reading sequence. Preserve only turns supported by the actual discussion; do not invent a trajectory or turn repetition, pauses, and unresolved questions into inevitable progress toward a conclusion.

Keep the synthesis distinct from the chronological record. Make consequential compression, inference, and reorganization visible, and link the relevant records or exchanges when available. Never replace, overwrite, or silently repair the original Q&A. Return the synthesis for author review; do not present model-selected turning points as the writer's confirmed account.

Return the synthesis in the requested form, in the response when no separate saved synthesis is requested. Existing checkpoint rules still govern preservation of the underlying multi-turn dialogue: a synthesis request authorizes the applicable session record, but not a new card. Do not automatically create a separate synthesis file, directory, card type, or a recurring end-of-answer summary. Follow the writer's explicit preservation scope and the existing card-selection rules.

Keep reconstruction of how the source became clearer in reading. When the writer wants to develop their own judgments or connections, hand that work to `thinking-skill`; when they request continuous exposition, a learning article, or a review, use the target-language writing skill (`writing-skill` for English prose; `writing-skill-zh` for Chinese prose). Do not route ordinary source-understanding changes to meta-reflection. Reflection on learning methods, mastery, or future direction requires the writer's explicit invocation of that skill.
