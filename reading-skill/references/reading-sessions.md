# Reading Q&A sessions

## Function

A reading-session record preserves how source understanding developed before selective synthesis. Keep it chronological and minimally edited. It is provenance for later reading cards, not a card itself and not an argument map or article commentary.

Choose the record language from the writer's explicit request, the active record, or the local dialogue when no record exists. Render all headings, field labels, and status labels naturally in that language. Preserve each writer question in the language in which it was asked and preserve quotations in the source wording actually inspected.

## When to preserve one

In a declared local reading project, a dialogue becomes eligible for preservation when it contains multiple substantive source questions. Do not write it immediately for that reason alone. Promote it to a session record only at a writer-confirmed checkpoint when:

- the writer asks to save, pause, close, synthesize, or change phase;
- the writer confirms a checkpoint proposed by Codex; or
- the writer directly requests one or more reading cards that will draw on the dialogue.

Codex may propose a checkpoint when a coherent line has reached temporary stability, the writer appears to be changing topics, several distinct reusable units have emerged, or the discussion is becoming long enough that a recoverable boundary would help. Ask once and continue the dialogue if the writer declines or does not accept. A proposal alone is not authorization to write a file.

Treat the ongoing chat as transient working state, even when the product retains its history. Do not create a project artifact for a one-off question unless the writer asks. During an active session, append live only when requested; otherwise wait for a writer-confirmed checkpoint.

Once promoted, keep the session as persistent provenance rather than temporary cache. Preserve it before creating any card that draws on it.

## Minimal structure

The English labels below identify semantic fields; localize them when the record is in Chinese.

```markdown
# Reading Q&A: Topic

## Session information

- Bibliographic and source identity:
- Reading basis and actual visible coverage:
- Locator system and extraction limits:
- Session date:

## Q&A record

### Q1

**Writer:** Original question

**Codex:** Answer given at the time

- Source basis and locator:
- Status: source reconstruction / model interpretation / needs verification
- Later correction:
```

Use only fields that carry information. Preserve the writer's questions verbatim. Preserve Codex's answers verbatim when practical; if a response must be shortened, mark it `[edited for length]` and do not strengthen its claims.

## Integrity rules

- Keep source reconstruction, model interpretation, writer response, and open questions distinguishable.
- Append dated corrections or links to later turns; never silently repair an earlier answer.
- Retain the order of questions, including detours and changes of understanding that matter.
- Add locators only when verified; do not manufacture retrospective precision.
- Let later reading cards link and selectively condense the session. Never delete the session because cleaner cards now exist.
