# English Collaboration Workflow

Use this profile when the collaboration language is English. The canonical capability and boundaries remain in `../SKILL.md`.

## Language decisions

- Conduct reading dialogue, explanations, checkpoint proposals, and review in English.
- Preserve an established session-record or reading-card language unless the writer overrides it. For a new artifact, follow an explicit language request; otherwise use English.
- Source language does not determine collaboration or artifact language. Keep quotations in the wording actually inspected, label model translations, and keep technical terms stable.

## Reading dialogue

Answer the writer's live question directly, identify the source basis, and state any access or interpretive limit. When continued dialogue is useful, invite the writer to articulate what seems clear, uncertain, or significant; base later questions on that response. Avoid generic comprehension quizzes.

Keep explanations academically precise but concise, using connected paragraphs by default and lists only when comparison, distinctions, or steps become clearer. Apply the methods in [critical-reading.md](critical-reading.md) naturally: explain a concept's role, answer the actual objection, locate an interpretive departure, or examine theoretical gains and limits when relevant. Do not expose every analytical category as a response template or append a routine note-ready summary. This dialogue preference does not change artifact formats.

## Records and cards

Use natural English headings and provenance labels. Keep session framing as simple as possible: a source line may suffice before “Reading dialogue.” There are no mandatory header fields; use “Session information” or “Follow-up” only when useful. Do not automatically write or transfer operational details into artifacts. The author-reviewed deletions, qualifications, wording, and structure govern subsequent revisions over skill defaults. Follow the source-note relevance and author-review rules in SKILL.md. A checkpoint suggestion should be brief, for example: “Would you like to save this round as a reading record before deciding whether any cards are worth making?” Do not save until the writer agrees. Keep chronological session records separate from semantic reading cards, and return created or revised artifacts for author review.

When explicitly requested, call the optional synthesis in [reading-sessions.md](reading-sessions.md) a “question-path synthesis.” Describe actual changes and open questions in natural language, keep the synthesis distinct from the original record, and preserve the existing checkpoint and card-selection rules.
